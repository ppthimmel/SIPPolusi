# Replay melalui gateway lokal

Sembilan permintaan sepeda untuk satu OD Jakarta dan α = 0, 0,5, 1 (tiga pengulangan masing-masing) dikirim melalui gateway → Cache API → planner → PIC A dan cache polusi dari replay TI-AI-11. Seluruhnya HTTP 200, `route_source=policy`, `preference_applied=true`, `morl-route-policy:2`, dan tidak ada fallback polutan maupun fallback rute. Median waktu klien 1.279 ms; ini termasuk komunikasi HTTP lokal dan respons, pada stack lokal yang hangat, bukan SLA atau ukuran populasi. Benchmark v2 berjalan bersamaan dan dapat memengaruhi waktu ini. Hasil lengkap termasuk request ID, metadata dan waktu ada di [gateway-results.json](gateway-results.json).

Permintaan jalan kaki mengembalikan HTTP 200 dengan `route_source=baseline`, `preference_applied=false` dan `fallback_reason=model_unavailable`. Preferensi tidak valid (0,8 + 0,8) mengembalikan HTTP 400 `invalid_request`; hasilnya di [gateway-failures.json](gateway-failures.json). Semua respons yang berhasil menandai `data_stale=true` karena window 09:00 UTC telah melewati batas kebaruan. Ini adalah perilaku yang dilaporkan, bukan data live terkini.

Window tersebut dihasilkan sebelumnya oleh Worker menggunakan kedua model spasial dan ditulis ke cache; [lineage](../inputs/spatial-lineage.json) dan [bukti replay TI-AI-11](../../TI-AI-11/container-verification.md) mencatat tahapnya. Pengukuran baru ini dimulai dari cache yang telah tersedia, bukan menjalankan akuisisi → Worker → gateway dalam satu siklus tanpa putus. Hanya satu OD dan dua jenis kasus gagal/alternatif diuji; ini tidak membuktikan ketersediaan sumber upstream, ketahanan beban, timeout, atau performa produksi. Pengujian diulang menggunakan `scripts/benchmark_ti_ai12_gateway.py` dan `scripts/verify_ti_ai12_gateway_failures.py` pada jaringan Compose terisolasi dengan registry, database, Cache API dan gateway yang sama; respons dan waktu dapat berbeda pada run berikutnya.
